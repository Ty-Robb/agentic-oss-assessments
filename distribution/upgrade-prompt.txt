<week_1_guardrails>
1. Single-source instructions:
   - Keep root AGENTS.md concise and open with the exact local check command. Move long reference material into docs/.
   - Put a 1-line `@AGENTS.md` include in CLAUDE.md (safer than symlinks on Windows; never overwrite an existing CLAUDE.md without merging its unique rules first).
   - Every new rule must cite a real bug, incident, or failure mode. Prefer deleting an instruction to hedging it.
   - Add four compact invariants:
     * Choose good compromises: prefer idempotency key + check + retry over speculative abstractions.
     * Doc voice: avoid filler ("It's not X, it's Y", "robust", "seamless", "and that matters"); integrate doc edits instead of appending.
     * Multi-agent Git safety: never run `git add -A`, `git stash`, or `git reset --hard`; never kill processes by name pattern.
     * Tests are the exception: prove behavior by running the real app/CLI; commit automated tests only where a silent regression is expensive (parsers/codecs, security boundaries, persistence/migrations, concurrency/state machines, cross-platform paths). Delete brittle mock/UI tests you touch instead of updating them.

2. One cached diff-scoped local check:
   - Wire or document one fast diff-scoped check command (e.g. `check:changed` or `verify`).
   - State in AGENTS.md: run it once when done editing; if cached/passing, do not also re-run the full typecheck, linter, or full test suite, and never pass `--no-verify`.

3. Honest PR template & review hygiene:
   - Add three compact sections to the PR template:
     * `### Observed / Not run` (exact commands run, observed output, and what was skipped).
     * `## Performance` (hot-path impact; explicitly allow `None, because ...` so agents do not invent benchmarks).
   - Keep local QA screenshots/logs gitignored and fail CI if scratch or evidence files get tracked.
   - Only create `REVIEW.md` if you can seed it from real PR review catches in git/`gh` history; if history is unavailable, skip it rather than fabricating rules.
</week_1_guardrails>
